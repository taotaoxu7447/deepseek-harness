# @deepseek-ai/dsh-client-ui-remote

[English](README.md) | 中文

主界面上的远程设备入口：位于 Settings 旁的侧栏底部触发器，其弹层列出 `remote` RPC 域的设备名册及实时隧道相位，执行连接/断开动作，并以两种方式打开一条已就绪隧道的 UI。名册的编辑仍在「设置 → 插件」（[`dsh-client-ui-settings-plugins`](../ui-settings-plugins/README.md)）里分阶段进行；本包是「连接并打开」的路径，让一台已配置的设备不再需要绕道设置页。

触发器是 `sidebar.footer.action` 的占用方，渲染与其他底部动作一致的 42px 行 / 36px 导轨圆形几何。只要任一隧道处于活跃，触发器上就出现状态点——就绪优先于连接中，连接中优先于失败——全部隧道静止时状态点消失。构造时的一次 `remote.list` 引导轮询喂给这颗状态点（Host 启动时自动连接的隧道无需打开任何东西即可显示）；持续的 2 秒轮询只在弹层打开时运行，因为弹层是唯一关注相位变化的界面。

就绪行提供两种打开手势。**在标签页打开**通过 `ctx.layout.openRemoteTab` 把隧道 UI 摆进窗口标签页，本地会话与任意多个远程因此共享一个窗口，经标签条切换。**在新窗口打开**以新浏览上下文打开隧道 URL，并把设备显示名挂在 `dshRemoteLabel` 查询参数上：普通浏览器会打开一个标签页并忽略该参数，而 macOS 外壳会把这类 URL 路由进一个以远程机器名作为标题副标题的独立应用窗口。

弹层底部的添加设备表单就地扩展 `remote` 设置段：显示名称、SSH 目标（`~/.ssh/config` 里已有的别名）、可选的远程/本地端口，以及自动连接。校验是最小且本地的——目标必填，端口必须能解析进 1–65535——勾选自动连接的设备保存后立即连接。名册写入扩展的是已存储的列表而非轮询视图，所以照 RPC 答复重新添加绝不会丢掉一台 Host 尚未为其建出隧道的已配置设备。

文案走本包自己的 `remoteEntry` locale 命名空间；样式只用 token。

## 模型体验

无，因为本包为人类渲染 Host 上报的隧道状态，不触及 prompt、消息、schema、流或工具结果。

#### KV Cache effect

无；本包从不组装或发送 provider 请求。

## 已知限制与暂缓事项

- **同窗口标签页要求回环远程 UI 允许被嵌入** —— 标签页把远程页面摆进 iframe，所以将来若给 webserver 加上 `X-Frame-Options` 或阻止嵌框的 CSP，就必须同时换一种同窗口方案。
- **新窗口手势依赖原生外壳的路由** —— 在普通浏览器下它就是一次普通的 `window.open` 标签页；只有 macOS 包装层会把它变成带标题、带独立 Dock 图标的应用窗口。
