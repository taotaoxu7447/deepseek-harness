# Agent Note：视觉链卡片——优先级链、拖拽排序、行收起与密钥草稿回显

状态：已实现

[English](2026-08-17-vision-chain-priority-drag-ui.md) | 中文

## 问题

视觉链的语义——最上面的后端先服务，耗尽尝试预算的后端降级到下一顺位——此前只用文字标签（「优先级 N · id」）加每行的上移/下移/移除按钮表达。用户无法把链条看成链条，三个以上后端靠反复点单步按钮重排既繁琐又容易出错。

## 决策

**把链条画出来**：每个后端行现在是带边界的卡片，行首包含拖拽手柄、圆形优先级徽章（位置序号）、以模型为主的标题和协议 chip；停用的行（`enabled: false`）整体变淡并佩戴「已停用」chip。相邻两行之间的连接线写明降级去向——「失败 N 次后由下一顺位服务」——N 读取尝试次数草稿（留空继承 Host 默认 2）。优先级含义现在由文档中的位置承载，而不是标签。

**拖拽排序，保留按钮**：行首 ⋮⋮ 手柄发起原生 HTML5 拖拽（`draggable` + `dataTransfer`），任意行接受 dragover，落点通过新增的绝对定位 face 动作 `moveRowTo(from, to)` 提交；上移/下移按钮保留为键盘可达路径。拖拽状态（源序号、悬停标记）只存在于卡片组件的 React state——控制器 store 只在提交点（drop）感知拖拽，保存/放弃绝不可能观察到半途的拖拽。模式沿用既有 `ui-workspace` 行拖拽，为至多五条的后端列表做了简化：不做插入标记，落在行上直接提交。

**收起为行首以便排序**：每行的 ▾ 按钮隐藏其字段（body 上的 `hidden`，草稿因此存活），「添加后端」旁的「全部收起」一次收起整条链；收起的行仍带拖拽手柄，长链的重排在紧凑的行首之间完成。收起状态按稳定的 `row.id` 记录，重排后跟随行走。

**密钥框回显草稿**：此前密钥输入框绑定硬编码的空串，受控重置吞掉了每次击键——用户无法判断输入是否生效。快照现在携带 `rowKeys`（用户自己输入的内容，绝不从凭据存储回读），密码框以掩码点回显，并挂「已填写」徽章直到保存落盘；保存后的 reseed 清空草稿，由「已配置」徽章承接。

## 备选方案

**插入标记拖拽（完整 `ui-workspace` 模式）**。落在行间并渲染标记线是更丰富的交互，但它让拖拽状态（源之外的标记位置）和测试面翻倍；至多五条的列表上，落在行上的语义已经明确。

**点击升位或位置下拉**。每行一个「优先级」下拉要求用户对着数字推理，而不是直接操作眼前可见的空间顺序；拖拽加单步按钮同时覆盖粗调与微调。

## 影响

- 行的 React key 从渲染序号改为稳定的 `row.id`，重排的行不再残留按序号复用的 DOM 状态。
- `moveRowTo` 是唯一的重排操作；`moveRow(index, ±1)` 现在经由它实现，按钮与拖拽共享同一组守卫（同位置 no-op、越界忽略）。
- 连接线文案读取尝试次数草稿，重试预算被编辑时降级说明即时跟随。
- 模型可见⟺可记录 不受影响：这只是渲染器与控制器改动，设置文档与线路格式均未变化。
