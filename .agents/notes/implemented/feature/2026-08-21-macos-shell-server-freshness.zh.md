# Agent Note: macOS 壳的服务器新鲜度检查

Status: implemented

[English](2026-08-21-macos-shell-server-freshness.md) | 中文

## 问题

macOS 壳只是套在 `http://127.0.0.1:3080/` 上的哑 WKWebView，其生命周期策略会复用任何应答 200 的服务器——永远。重新构建落入 `lib/`，但长驻服务器进程早于这次构建，于是每次更新看起来都「没进 app」：用户一直被服务上一个构建的 UI，直到碰巧手动杀掉进程。壳无法区分「一个健康的服务器」和「当前构建的服务器」。

## 决策

由服务器自己回答 staleness 问题。`web-app` 组合包插件注册了一条精确匹配的管理者路由 `GET /__dsh_health`，返回 `{startedAt, builtAt, stale}`（epoch 毫秒）：进程启动时间、完整构建记录 `.dsh-build/client-build-environment.json` 的修改时间（每次请求时读取，运行期间落地的构建立即可见），以及 `stale = builtAt > startedAt`。没有该记录的 checkout 应答 `builtAt: null`，永不报告 stale。该路由经 webserver 的精确匹配分发先于 SPA 回退；端点出现之前的旧构建在该路径仍会以 HTML 应答 200，JSON 解析先排除它，随后根页面里的 `__DSH_BOOT__` 标记把它指纹化为旧版 dsh（可提议重启，只是时间戳未知），从而与占用端口的无关进程区分开——后者壳绝不触碰。

壳在启动时和每次 Dock 重开时探测该端点，使用 ephemeral `URLSession`，缓存的 200 永远掩盖不了新构建。当 payload 为 stale 且用户没有拒绝过这个确切的 `builtAt` 时，应用级模态弹窗列出两个时间戳并提供「Restart Server」/「Later」；拒绝则按构建戳休眠，直到下一次构建改变它。重启流程对端口监听者先 SIGTERM（cordis 清理会干净地关闭会话与 SSH 隧道），轮询端口关闭，宽限期过后才升级为 SIGKILL，然后重新拉起 `~/bin/dsh-serve`，等待端口重新应答，并把窗口重载回本机 Host。停不掉或起不来会弹出专门的告警，给出手动恢复路径。

## 备选方案

- **壳自己 stat 仓库文件**。否决：壳需要知道 checkout 路径与构建布局，而这些事实它刻意不持有；服务器两者都知道，把 `stale` 放在服务端计算让壳可替换（Linux 壳、launchd 监督者），共用同一个单端点契约。
- **用 `bin.js` 的 mtime 当构建戳**。否决：增量 tsc/tsdown 可能不会重写未变化的产物，真实重建可能完全不碰启动器的 mtime；构建记录在每次完整构建末尾都会被重写，且本来就为客户端产物背书。
- **提交哈希比较**。否决：脏树重建（正常的 改-构建-试 循环）HEAD 不变，哈希相等会把 stale 进程误报为「新鲜」；真正的问题是时间性的——磁盘构建是否晚于进程。
- **无提示自动重启**。否决：重启会打断运行中的任务，而且壳的既有约定是关窗绝不停后端；时机由用户选择，弹窗也如实说明任务会中断、会话历史会保留。

## 影响

端点出现之前构建的服务器同样会被接住：启动标记指纹让它们以无时间戳的文案进入可提示状态，因此切换不需要手动 kill。checkout 之外的安装部署没有构建记录，永不被打扰。弹窗只在启动与重开时触发，每次 app 运行内对每个构建戳至多一次（旧版服务器构建戳未知，每次运行至多一次）。WKWebView 页面缓存是另一层更小的 staleness，由 ⌘R 处理。另外，`build.sh` 现在先删除旧 bundle 再拷贝：对正在运行的 app 做合并拷贝会在存活进程脚下截断二进制，之后每次启动都会在无辜的代码帧里崩掉——首次切换时的崩溃报告正是这个原因。同一个构建里还有第二个优化器陷阱：全模块死代码剥离会移除编译器看不到 Swift 侧使用者的类，即使 AppKit 在运行时会用到——`ComposerDropBridgeView` 就从 `-O` 二进制里消失了（文件夹拖放落空到页面的纯图片路径），直到一次自引用读取让它可达；远程辅助 app 复用同一份编译源，一次修复同时覆盖两者。

## 测试

单测：`serverHealth` 归约（构建更新/相同/更旧/缺失）与 `lastBuildAt` 对临时记录的读取（mtime 生效、无记录根目录 → null）。路由：通过捕获的 `webServer.register`——GET 应答 payload、非 GET 得到带 `allow: GET` 的 405、dispose fiber 后注册被移除。真实组合：浏览器启动测试的监听服务器应答 `/__dsh_health` 的合法 payload 并拒绝 POST。
