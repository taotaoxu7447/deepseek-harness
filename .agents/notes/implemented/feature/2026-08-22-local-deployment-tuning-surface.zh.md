# Agent Note: 本地部署调优面——可配置的流式空闲超时与按模型的输入模态声明

Status: implemented

[English](2026-08-22-local-deployment-tuning-surface.md) | 中文

## Problem

设置平面的两个缺口专门咬本地部署。其一，流式空闲超时在两个 LLM 适配器里写死为五分钟：本地引擎服务大型 MoE（或冷的投机解码槽位）时，预填期间合法地静默超过这个值是常态，适配器却会把请求中止。其二，提供方的模型行无法声明视觉能力，本地支持视觉的模型永远收不到图片——DeepSeek 适配器的目录按设计全在本地，界面上没有任何东西能把一行手工声明的模型标为支持图像。

## Decision

默认流式空闲超时在两个适配器中一并改为十分钟（`llm-pi-ai` 的 `DEFAULT_STREAM_IDLE_TIMEOUT_MS = 600_000` 与 `llm-deepseek` 同值），且提供方编辑器的自定义折叠区在两个家族的 `baseURL` 旁新增**流式空闲超时**字段：界面以秒为单位（占位符写出继承到的 600），存储进 profile 时是毫秒，留空即继承。该字段沿用卡片既有的容量字段模式——文本缓冲、拦住「应用」的校验、每次编辑一条 `set`/`unset` 路径 op——两个适配器的 README 都记录了这个新默认值。

按模型的**输入模态胶囊**放进两个模型编辑器，与它们镜像的推理档位胶囊相邻：`text` 是锁定的下限（永远打开，从不单独落盘），点击 `image` 即声明视觉支持——pi-ai 模型行存为 `input: ["text", "image"]`，DeepSeek 行存为 `inputModalities`；再关掉图像会整个丢弃该键，未声明的行继续保持继承。共享的 `ModalityChips` 组件持有解析与开关修复逻辑（只有 `["image"]` 的行会愈合回文本下限），分别落座于 `ModelListEditor` 与 `DeepSeekModelsEditor`。

## Alternatives considered

**用环境变量或 cordis.yml 开关调超时。** 否决：这个值随部署、随路由变化，这正是设置界面存在的理由；一个藏起来的开关不会帮到那个撞上中止的用户。

**提供方级的模态开关。** 否决，理由与推理等级保持按模型相同（记录在 Models 页 README）：同一提供方下各模型并不一致，提供方级的开关会把每一行不同的模型都声明错。

**自由文本的模态列表。** 否决：适配器建模的是一个封闭集合，两个胶囊已覆盖当前所有取值，无需再引入一套校验词汇。

## Consequences

本地部署不再在五分钟静默线上无配置地死掉，需要更长的部署按路由调大，不必碰 `settings.yaml`。存储值是毫秒而界面说秒——解析/格式化这对函数持有这份不对称。模态声明是纯增量且无默认：既有配置行为完全不变，直到某行被显式标为支持视觉。

## Testing

解析/格式化辅助函数、两个编辑器的胶囊行为（开启、关闭、丢弃键、隐藏字段保留）与提供方表单字段（秒→毫秒写入、继承占位符、非法拦截）都有单测；两个适配器的既有套件钉住了新默认值。
