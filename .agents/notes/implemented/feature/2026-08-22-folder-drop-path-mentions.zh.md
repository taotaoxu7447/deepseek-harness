# Agent Note: 文件夹拖入输入框——原生拖放桥与路径提及

Status: implemented

[English](2026-08-22-folder-drop-path-mentions.md) | 中文

## 问题

输入框此前只把拖放当作图片接收：document 级处理器读取 `dataTransfer.files`——一个平铺的 File 列表，拖入的文件夹在其中只是一个空壳（无路径、无字节、type 为空），随后被图片格式校验拒绝。"让 agent 看这个文件夹"这一手势完全不存在，而且浏览器 API 在设计上就不向页面暴露拖放项的绝对路径，无法由此实现。

## 决策

两条 intake 路径，外加一处契约新增。

**macOS 壳（携带路径的情形）。** 一层透明的 `ComposerDropBridgeView` 覆盖在两个应用目标（主壳与远程 helper）的 WKWebView 之上，只注册 `.fileURL` 拖拽类型。AppKit 按几何关系（注册 + frame 包含）解析拖放目标，因此覆盖层的 `hitTest → nil` 让所有点击照常落在页面上，同时仍能接收 Finder 拖放。由于 AppKit 在顶层目标拒绝时不会把拖放转给下层视图，覆盖层接受*所有*文件拖放再做再分发：文件夹与非图片文件成为携带绝对路径的提及条目；图片文件（UTI 判定，单张 ≤32MB，单次 ≤16 张）读出字节以 base64 内联。载荷经 `window.__dshNativeDrop(<json>)` 进入页面；接收器由当前挂载的 `ComposerAttachments` 注册、卸载时注销（身份守卫，过期的会话不会吃掉继任者的拖放）。图片条目重建为 File 后走与页面级拖放完全相同的 `onAddImages` intake，校验、toast 与草稿附件栏行为不变。

**提及插入。** `conversation.input.attachments` 的持有方 props 新增 `onAddPaths`；InputBar 经机器唯一的 `setDraft` 写入路径把每个路径追加进草稿，格式由共享的文件引用语法产出（`formatFileMention`：目录带尾斜杠，含空白的路径加引号）。纯文本即模型形态——胶囊外观是机器扫描派生的装饰而非状态——因此无需铸建 occurrence，而已有的 `FILE_REFERENCE_PROMPT` 本就告诉模型 `@` 前缀路径是用户显式引用、要用工具读取的文件。

**浏览器回退（无原生壳）。** 含文件夹的拖放经 `webkitGetAsEntry()` 检出后递归遍历（`readEntries` 分页，512 个条目预算抵御 node_modules 形状的树），把其中找到的图片按正常路径附加。文件夹里没有可附加图片时不产生任何动作——浏览器无法引用路径，而拖放邀请层本就把拖放表述为图片。

## 备选方案

**导航拦截。** 对文件夹拖放跳过 `preventDefault`、在 WKNavigationDelegate 里拦截随之产生的 `file://` 导航，无需覆盖层即可泄漏路径。否决：WebKit 是否会为拖入的*目录*发起导航，不做一次人工拖放无法验证；而在普通浏览器里同一手势会把标签页导航走、丢掉会话。现在页面始终阻止默认行为，两种运行时行为一致。

**覆盖层只拒绝非文件夹拖放。** 被 AppKit 语义否决：最顶层已注册目标返回无操作时，拖放不会再提供给下层视图——拒绝会顺带掐死原本可用的图片拖放。

**把文件夹内容作为附件上传。** 否决：没有路径时文件对 agent 只是不透明的字节，而绝对路径提及让它的 fs 工具直接作业——能力严格更强；具备视觉的部署仍可让模型按路径读取其中的图片。

## 影响

在应用内，文件拖放不再到达页面：Finder 拖放期间不再出现 `DropOverlay` 邀请层与忙碌态的 `dropEffect` 光标（覆盖层直接应答 `.copy`），输入框忙碌时的拒绝也从可见的禁用态变为接收器内的静默忽略。页面内部的拖拽（工作区行、文本选择）从不携带 `.fileURL`，不受影响照常落到页面。混合拖放按类型分流：图片附加，其余成为提及。32MB/16 张的桥上限只是传输护栏，输入框自身的 `imageLimits` 仍是权威。桥接收器是 `window` 全局，同一时刻只有一个已挂载的输入框持有它——若将来出现同时挂载两个输入框的形态，需要引入路由键。

## 测试

`ui-attachment` 规格覆盖条目树遍历（分页、失败的叶子、readEntries 错误、预算、非图片与未知类型跳过）、桥载荷解码（字节/文件名/MIME）、组件接收器（图片→草稿、路径→提及、`canAcceptDrop` 门控、对继任者安全的卸载），以及浏览器文件夹拖放分流。`ui-conversation` 规格覆盖 `intakePaths`（斜杠/引号、空草稿与空白结尾草稿，以及锁定/忙碌/无机器/空批次/不可表示路径的拒绝）。壳的一半由人工冒烟验证：把文件夹、图片、混合批次拖进应用输入框，并确认页内拖拽（工作区行）仍正常。
