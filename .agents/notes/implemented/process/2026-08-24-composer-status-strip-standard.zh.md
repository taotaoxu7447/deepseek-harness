# Agent Note: Composer 状态条遵循官方紧凑行

Status: implemented

[English](2026-08-24-composer-status-strip-standard.md) | 中文

## Problem

`conversation.input.dock` 列表接受来自独立插件的条目，但 slot 只负责组合，不负责呈现。当每个插件自行决定收起高度、外边距、表面、阴影与信息密度时，即使宽度已经对齐，堆栈仍会显得不整齐，而且组件 margin 会与父级拥有的 gap 重复叠加。将 fork 专用插件带过官方 UI 更新时，这种漂移还会增加冲突。

## Decision

独立状态条与摘要条遵循 [Composer 状态条参考](../../../../docs/composer-status-strips.zh.md)规定的官方紧凑 Todo 行基线。父级堆栈拥有 6px gap，条目不增加纵向 margin。收起状态卡片使用共享 dock 宽度轴、36px 内层行与 38px 可见高度、tip 表面、一级边框、12px 圆角，并且没有组件专用阴影。

收起内容保持单行，在改变高度之前舍弃低优先级指标。展开详情可以在同一张有界卡片内增高，但常驻面板必须移出输入区堆栈。注册项的 `order` 只选择顺序，不产生视觉效果。

这是一项面向贡献者与插件作者的规范。它不声称每个现有 fork 专用条目都已符合要求；让既有条目符合规范属于单独的 UI 行为变更，需要独立验证。

## Alternatives considered

**保留组件自行拥有几何尺寸。** 这种方式保留了局部自由，但没有稳定的评审标准，允许 margin 与堆栈 gap 叠加，还会让每个新插件重新推导宽度和信息密度规则。

**把所有条目放大为插件卡片当前使用的 50px 样式。** 这样可以让当前两个插件卡片彼此一致，但会改变内建紧凑视觉基线，并扩大以后与官方更新对齐时需要处理的 fork 专用差异。

## Consequences

新增和修改后的状态条有了单一、可评审的目标，可以共存而不会累积间距。紧凑行限制了收起状态的信息密度，因此次要指标必须隐藏或移入展开区。在共享 UI 组件或自动视觉检查提供更窄的实现路径之前，这项规则仍由文档与评审执行。
